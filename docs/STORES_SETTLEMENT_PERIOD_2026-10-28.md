# STORES予約の入金対象期間・返金期限の検証（2026-10-28）

**対象**：Issue #2（実CSV適合）。今回の新規発見は、**予約・決済の日本時間の日付で入金対象月を分けると誤る**こと。顧客需要の一次証拠が増えたわけではない。

## 公式一次資料で確認できた事実

### 1. 通常の月次振込はUTCで決済対象月が決まる

STORES予約公式「売上金の入金サイクルについて」（**2026-06-22更新**）：
https://reserve-faq.stores.jp/hc/ja/articles/28713302057241

- 通常の月次サイクルは、決済の対象期間の翌月25日（土日祝は翌営業日）に入金。
- **決済日時はUTC基準**。日本時間の月初 **1日00:00〜08:59** の決済は、UTCでは前月末のため、**その日本時間の月に入金される対象**となる。
- 公式の具体例：**8/1 01:00 JSTの決済 → 8/25入金**、**8/1 10:00 JSTの決済 → 9/25入金**。
- 週1回入金は水曜の境界・火曜入金、切替直後の旧月次分の順次入金、決済から25日経過後の火曜などの例外がある。**通常の月次ロジックを週次に適用してはいけない**。
- 入金額には決済手数料の控除があり、さらに2026-08-25振込以降は別途振込手数料の変更がある。繰越・返金・設定変更で実際の入金日・金額は変わり得る。

### 2. 予約キャンセルと返金の発生は同義ではない

STORES予約公式「事前クレジットカード決済の予約をキャンセルした場合の返金について」（**2026-08-27更新**）：
https://reserve-faq.stores.jp/hc/ja/articles/28712713337369

- 返金可能期間内の事前カード決済予約のキャンセルは、キャンセルと同時に全額自動返金。
- 返金可能期間は**通常の入金サイクル：予約完了から25日後の同時刻まで**、**短縮サイクル：予約完了から7日後の同時刻まで**。
- 期限を過ぎたキャンセルは可能でも、STORES予約上では返金されない。必要な返金は顧客と個別調整。
- カード利用明細への返金反映時期はカード会社によって異なり、翌月以降の返金・相殺もあり得る。

**設計上の禁止事項**：「予約ステータス=キャンセル」だけで「決済額が自動返金済み」「銀行入金から差し引くべき額が確定」と断定しない。実返金明細、予約完了時刻、当時の入金サイクル、返金実行状態が必要。

### 3. 入金予定内訳の形式はまだ未確定

公式「事前クレジットカード決済売上の入金予定額を確認する方法」（**2026-08-04更新**）：
https://reserve-faq.stores.jp/hc/ja/articles/28713301530137

- 管理画面の入金ページから「内訳（予約）」と「内訳（回数券・月謝）」を別々にダウンロードできる。
- 予約内訳だけでは全体入金を説明できず、予定額は確定前に変わり得る。
- **FAQ本文にはCSVの確定したヘッダー、決済ID、返金ID、振込IDの一覧はない**。ダウンロード形式を選択する説明はあるが、特定のCSV列構成を断定できない。

## 合成データで検証できること（実CSV・銀行入金ではない）

`src/settlement-period.mjs` の `classifyMonthlySettlementPeriod` は、**明示的な時差付きの決済タイムスタンプ**と `monthly` / `weekly` の入金サイクルを入力とする研究用関数。

| 合成決済日時 | UTCの対象決済月 | 名目上の振込月 |
| --- | --- | --- |
| 2026-08-01T01:00:00+09:00 | 2026-07 | 2026-08 |
| 2026-08-01T08:59:59+09:00 | 2026-07 | 2026-08 |
| 2026-08-01T09:00:00+09:00 | 2026-08 | 2026-09 |
| 2026-08-01T10:00:00+09:00 | 2026-08 | 2026-09 |
| 2027-01-01T08:59:59+09:00 | 2026-12 | 2027-01 |

- `weekly` は `REQUIRES_CONFIRMATION` を返し、対象月を推測しない。
- 時差なしの日時、日付だけの入力、不正日付は拒否する。
- `nominalPayoutMonth` は**月次の名目上の振込月**であり、実際の振込実行や会計計上日を示さない。繰越・祝日・組戻し・切替・返金・手数料・契約条件は計算しない。
- この研究用関数は**現行アプリ、予約CSVの列マッピング、仕訳候補出力に接続していない**。公式CSVに実際の時差付き決済日時列があることも未確認。
- テスト：`node --test tests/settlement-period.test.mjs`（月初の境界、年越し、時差、週次未対応、入力異常、うるう年）。

## 実CSV適合ゲートの優先検証順

1. **入金内訳（予約）**の実ヘッダー・決済日時の形式・タイムゾーンの有無・決済IDと予約IDの粒度を確定する。
2. **入金内訳（回数券・月謝）**を予約分と別に検証し、振込IDや対象期間の紐付けを調べる。
3. **入金履歴（確定額）**と入金予定額の区別、繰越、実際の振込日、振込手数料、決済手数料、返金を検証する。
4. 返金については**予約キャンセル日時と実返金実行日時を分ける**。期限切れの個別返金はSTORES外で処理される可能性があるため、元CSVだけで完結しないことを前提にする。
5. 公式の匿名サンプルまたは個別許諾済み匿名化サンプルを使ってから、実CSVへの対応を主張する。**実顧客データの無断取得・公開リポジトリへの保存は禁止**。

## 事業仮説と需要検証の関係

「日本時間で決済月を集計すると、STORES予約の入金対象月とずれることがある」という公式仕様上のギャップは、**手作業の入金照合で説明できない差分が発生する原因の候補**。実利用者がこの原因で何分困っているか、毎月2,980円を払うかは未検証。公式仕様の発見を有料顧客や一次体験談として数えない。
