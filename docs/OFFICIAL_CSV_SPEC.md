# 公式CSV仕様との照合（2026-10-26調査）

## 1. STORES予約：予約一覧CSV

公式FAQ（2026-08-04更新）によれば、管理画面から期間指定の予約一覧をCSV出力できる。個別ページ単位と、全予約ページの一括出力がある。期間未指定の個別出力では当月から3か月先までの予約が含まれるため、月次売上集計にそのまま利用しないこと。

- 出力方法: https://reserve-faq.stores.jp/hc/ja/articles/28712681987097
- 主な出力項目: https://reserve-faq.stores.jp/hc/ja/articles/28712690043033 （2025-04-07更新）

公式「主な出力項目」には、**金額、ステータス、支払ステータス、支払方法、申込日時、希望の予約日時、来客／キャンセル日時**が記載されている。ただし、この一覧は正確なCSVヘッダーの定義ではない。**決済日時、決済単位の一意ID、返金金額、手数料**は上記の「主な出力項目」では確認できない（項目が絶対に存在しないという意味ではない）。

### 実装上の判断

- 「予約日時」を決済日／会計上の取引日として自動マッピングしない。
- 「ステータス」は予約の状態、「支払ステータス」は支払の状態として区別する。CSVの正確なヘッダーは未検証なので、利用者が列を確認する。
- 予約ステータスにキャンセル・取消などの語が含まれる行は、支払済みでも仕訳候補から除外して要確認に分類する。予約ステータス未指定時にはキャンセルを検出できない。
- 現状の必須「取引ID」は、予約ページIDや会員番号では代替できない。決済・返金単位の識別子が得られるか要検証。
- 「金額」と「支払ステータス」があることだけでは、仕訳確定・売上計上時点・決済手数料の正確性を判断できない。
- 実際のヘッダー、ステータス値、レコードの粒度は匿名化された実CSVか正式サンプルで別途検証する。

## 2. マネーフォワード クラウド会計：仕訳帳CSV

公式「仕訳帳をインポートする」ガイド（**2026-07-09更新**）に従う。

https://biz.moneyforward.com/support/account/guide/import-books/ib01.html

公式ガイドの項目リストは **A列〜AA列の27列**。以前のMVPはV列までの22列で、公式の項目リストと不一致だったため修正した。

| 列 | 項目 | 本MVPの扱い |
| --- | --- | --- |
| A | 取引No | 空欄（既存仕訳との照合は不可） |
| B | 取引日 | 利用者が対応付けた日付。正当性は未検証 |
| C / K | 借方／貸方勘定科目 | 利用者指定 |
| I / Q | 借方／貸方金額(円) | 同一の正の整数 |
| S | 摘要 | 「予約 ID メニュー」 |
| D〜H、J、L〜P、R、T〜V | その他の項目 | 空欄（税区分など未設定） |
| W | 決算整理仕訳 | 空欄 |
| X〜AA | 作成日時・作成者・最終更新日時・最終更新者 | 空欄（インポートで未使用） |

公式ガイドでは**指定のサンプルフォーマットを使用する**こと、必須の取引日・勘定科目・金額、取引日の形式 `yyyy/MM/dd`、勘定科目30字以下、摘要200字以下、**インポートのたびに新規仕訳を登録する**ことが説明されている。

本MVPの27列ヘッダーと出力行長は単体テストで照合する。ただし、**公式サンプルファイル自体のバイト単位照合や会計画面への実インポート試験は未実施**であり、インポート成功は保証しない。

## 3. 次の検証ゲート

1. STORES予約の匿名化された予約CSVと、可能なら決済・返金データの正式サンプルを用意する（顧客の許諾が必要。公開GitHubへアップロードしない）。
2. 出力列名と識別子の粒度を確定し、予約／決済／返金の対応関係をテストする。
3. マネーフォワード管理画面から当該事業者用の公式サンプルフォーマットを取得して照合する。
4. 会計年度、科目、税区分、計上時点を専門家確認し、サンドボックス相当のテスト環境でインポートを確認する。
5. 上記が終わるまでは「仕訳候補CSV」以上の保証をしない。

## 4. 事業上の示唆（仮説）

予約一覧CSV単独では会計仕訳の正確性に必要な情報が不足する可能性がある。初期の価値提案は「**予約・支払状況の異常検出と月次照合の作業削減**」に置き、会計への直接投入は別機能として検証する。これはまだ顧客の支払意思を確認できていない仮説である。
