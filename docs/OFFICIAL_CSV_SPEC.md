# 公式CSV仕様との照合（2026-10-26調査）

## 1. STORES予約：予約一覧CSV

公式FAQ（2026-08-04更新）によれば、管理画面から期間指定の予約一覧をCSV出力できる。個別ページ単位と、全予約ページの一括出力がある。期間未指定の個別出力では当月から3か月先までの予約が含まれるため、月次売上集計にそのまま利用しないこと。

- 出力方法: https://reserve-faq.stores.jp/hc/ja/articles/28712681987097
- 主な出力項目: https://reserve-faq.stores.jp/hc/ja/articles/28712690043033 （2025-04-07更新）

公式「主な出力項目」には、**金額、ステータス、支払ステータス、支払方法、申込日時、希望の予約日時、来客／キャンセル日時**が記載されている。ただし、この一覧は正確なCSVヘッダーの定義ではない。**決済日時、決済単位の一意ID、返金金額、手数料**は上記の「主な出力項目」では確認できない（項目が絶対に存在しないという意味ではない）。

### 実装上の判断

- **2026-10-27追加：月次仕訳候補の対象月チェック**。予約一覧CSVは期間指定を誤ると複数月の予約を含む。仕訳候補CSVの出力前に任意の対象月（YYYY-MM）を指定できるようにし、選択した会計取引日が対象月から外れる行が1件でもあれば出力を停止する。元CSVの抽出期間や予約月とは別概念であり、月次の売上確定額・正しい計上日を保証しない。会計年度チェックと併用可能。合成CSVの単体テスト・Chromium画面テストで検証。実STORES CSVは未検証。

- 「予約日時」を決済日／会計上の取引日として自動マッピングしない。
- **2026-10-26追加**: 利用者が手動で「申込日時」「予約日時」「希望の予約日時」「来客日時」「来客／キャンセル日時」「キャンセル日時」を取引日として選択した場合も、会計取引日としての根拠が未確認なので全行を要確認に分類し、仕訳候補には出さない。日付の形式が正しくても決済日・売上計上日である証明にはならない。適切な取引日を確認したうえで別列を用意する必要がある。これは試作版の保守的な判断であり、STORESの公式CSVヘッダーの完全な検証を意味しない。
- 「ステータス」は予約の状態、「支払ステータス」は支払の状態として区別する。CSVの正確なヘッダーは未検証なので、利用者が列を確認する。
- 予約ステータスにキャンセル・取消などの語が含まれる行は、支払済みでも仕訳候補から除外して要確認に分類する。予約ステータス未指定時にはキャンセルを検出できない。
- **2026-10-26追加**: 公式FAQでは予約ステータスとして「確定」「キャンセル」「承認待ち」を区別している。支払済みでも「承認待ち」を仕訳候補として扱うのは危険なため、**予約ステータス列が指定された場合、明示的に確定と認識できる状態以外は要確認**にする。現在の許容値は「確定」「予約確定」「confirmed」のみ。後二者は互換性のための暫定表記であり、STORES実CSVの正式値として検証済みという意味ではない。未知の値（「保留」「仮予約」等）は誤って自動候補にせず、要確認にする。
  - 予約ステータス（確定・キャンセル・承認待ち）: https://reserve-faq.stores.jp/hc/ja/articles/28718514774169 （2024-03-18更新）
  - 予約リクエストは事業者の承認が必要: https://reserve-faq.stores.jp/hc/ja/articles/28712689940505 （2025-09-24更新）
  - **注意**: 公式FAQの画面表示と実CSVの列値が同一とは未確認。確認済みステータスでも売上計上の正当性は保証しない。
- 現状の必須「取引ID」は、予約ページIDや会員番号では代替できない。決済・返金単位の識別子が得られるか要検証。
- 「金額」と「支払ステータス」があることだけでは、仕訳確定・売上計上時点・決済手数料の正確性を判断できない。
- 実際のヘッダー、ステータス値、レコードの粒度は匿名化された実CSVか正式サンプルで別途検証する。

### 購入履歴CSV・入金予定内訳は予約一覧CSVと別のデータ源（2026-10-27追加）

STORES予約とレジの連携に関する公式FAQ（2025-12-04更新）は、**顧客ごとの購入履歴CSV**に「購入日時」「商品名」「金額」「支払い方法」「スタッフ」「ステータス」「オーダー番号」「顧客名」が含まれると記載する。ただし、これは予約一覧CSVの正式ヘッダー一覧ではなく、また「購入日時」が会計上の売上計上日・決済確定日だと保証するものでもない。

- 購入履歴CSVの項目: https://reserve-faq.stores.jp/hc/ja/articles/30386678275353
- **実装対応**: 「購入日時」を取引日として自動選択しない。手動で選択しても仕訳候補には出さず、要確認にする。汎用の「ステータス」は支払ステータスと決めつけない。

公式FAQ（2026-08-04更新）によれば、**事前決済売上の入金予定内訳**は予約と回数券・月謝で別々にダウンロードできる。入金額確定前の予定額は、キャンセル・返金等で変わりうる。したがって、予約一覧CSVだけで銀行入金と一致することを前提にした自動仕訳は不適切。

- 入金予定額と内訳: https://reserve-faq.stores.jp/hc/ja/articles/28713301530137
- **未検証**: 内訳ファイルの正確なCSVヘッダー、入金確定前後の粒度、手数料・返金明細、購入履歴と予約一覧のID対応。これらの実データを無断取得しない。

## 2. マネーフォワード クラウド会計：仕訳帳CSV

公式「仕訳帳をインポートする」ガイド（**2026-07-09更新**）に従う。

https://biz.moneyforward.com/support/account/guide/import-books/ib01.html

公式ガイドの項目リストは **A列〜AA列の27列**。以前のMVPはV列までの22列で、公式の項目リストと不一致だったため修正した。

| 列 | 項目 | 本MVPの扱い |
| --- | --- | --- |
| A | 取引No | 空欄（既存仕訳との照合は不可） |
| B | 取引日 | 利用者が対応付けた日付。正当性は未検証 |
| C / K | 借方／貸方勘定科目 | 利用者指定 |
| I / Q | 借方／貸方金額(円) | 同一の正の整数 |
| S | 摘要 | 「予約 ID メニュー」 |
| D〜H、J、L〜P、R、T〜V | その他の項目 | 空欄（税区分など未設定） |
| W | 決算整理仕訳 | 空欄 |
| X〜AA | 作成日時・作成者・最終更新日時・最終更新者 | 空欄（インポートで未使用） |

公式ガイドでは**指定のサンプルフォーマットを使用する**こと、必須の取引日・勘定科目・金額、取引日の形式 `yyyy/MM/dd`、勘定科目30字以下、摘要200字以下、**インポートのたびに新規仕訳を登録する**ことが説明されている。

出力前監査では、任意項目である「取引No」が入力されている場合は**半角数字1〜9桁**、また「摘要」は**200文字以内**であることも検査する。取引Noが空欄の場合は従来どおり警告する（取引Noの付与は会計側の二重取り込みを防ぐ保証にはならない）。この条件はマネーフォワード公式ガイドの項目リストに基づく。

**2026-10-27追記**: 公式ガイドは、現在選択している会計年度内の取引日だけをインポートできると明記する。任意で会計年度の開始日・終了日を入力し、仕訳候補の取引日が期間外なら出力前に停止するチェックを追加した。入力期間は利用者の申告であり、会計年度や売上計上日の正当性を自動判定するものではない。期間未指定ならチェックしない。

**2026-10-30：インボイス区分の空欄は「未判定」のまま取り込まれない（M3/Issue #2）**。MF公式の[仕訳帳インポートガイド（2026-07-09更新）](https://biz.moneyforward.com/support/account/guide/import-books/ib01.html)は、H列「借方インボイス」・P列「貸方インボイス」が空欄の場合、インポート時に**「適格」として扱う**と明記する。現行MVPは両列を空欄で出力するため、単に「税区分未設定」と警告するだけではこの既定動作を見落とす。出力前監査に**空欄インボイス区分の明示警告**を追加し、両列を設定した合成例では警告が消えることを回帰テストする。ただし「適格」と明示入力した場合もその税務上の妥当性は自動確認できず、出力の合格はMFへの実インポート成功・適格性・実CSV適合を保証しない。**本番投入禁止の現状は維持**する。

本MVPの27列ヘッダーと出力行長は単体テストで照合する。ただし、**公式サンプルファイル自体のバイト単位照合や会計画面への実インポート試験は未実施**であり、インポート成功は保証しない。

## 3. 次の検証ゲート

1. STORES予約の匿名化された予約CSVと、可能なら決済・返金データの正式サンプルを用意する（顧客の許諾が必要。公開GitHubへアップロードしない）。
2. 出力列名と識別子の粒度を確定し、予約／決済／返金の対応関係をテストする。
3. マネーフォワード管理画面から当該事業者用の公式サンプルフォーマットを取得して照合する。
4. 会計年度、科目、税区分、計上時点を専門家確認し、サンドボックス相当のテスト環境でインポートを確認する。
5. 上記が終わるまでは「仕訳候補CSV」以上の保証をしない。

## 4. 事業上の示唆（仮説）

予約一覧CSV単独では会計仕訳の正確性に必要な情報が不足する可能性がある。初期の価値提案は「**予約・支払状況の異常検出と月次照合の作業削減**」に置き、会計への直接投入は別機能として検証する。これはまだ顧客の支払意思を確認できていない仮説である。

## 6. 2026-10-28追記：入金対象月は決済日時のUTC基準で確認する

STORES予約の公式「売上金の入金サイクルについて」（2026-06-22更新）では、通常の月次振込について、**日本時間の毎月1日00:00〜08:59の決済はUTCで前月扱いとなり、同月25日の入金対象**になると説明している。例：2026-08-01 01:00 JSTは8月25日入金対象、同日10:00 JSTは9月25日入金対象。予約日・日本時間の決済日をそのまま入金対象月とみなしてはいけない。

また公式返金FAQ（2026-08-27更新）は、予約完了から通常25日、週次短縮7日を超えた場合は、予約キャンセルしてもSTORES予約内で自動返金されないと説明する。**キャンセルと返金は別のイベント**として扱う必要がある。

- 入金サイクル：https://reserve-faq.stores.jp/hc/ja/articles/28713302057241
- 返金期限：https://reserve-faq.stores.jp/hc/ja/articles/28712713337369
- [公式仕様・合成テスト・実CSV未検証項目の整理](STORES_SETTLEMENT_PERIOD_2026-10-28.md)

研究用 `src/settlement-period.mjs` と回帰テストを追加したが、**現行アプリには未接続**。実CSVに決済日時と明示的タイムゾーンが存在するか、実際の入金履歴と紐づくかは未検証。週次の振込対象期間や設定変更時の例外は自動判定しない。会計上の売上計上月は別途確認が必要。
