# 予約売上チェッカー（MVP / 試作）

STORES予約等のCSVをブラウザ内で解析し、重複・不正な日付や金額・要確認の支払ステータスを検出し、マネーフォワード クラウド会計「仕訳帳」向け**仕訳候補**CSVを作る実験的ツールです。

> **実運用不可の試作段階です。** STORES予約の実CSVサンプルでの互換テスト、実際のマネーフォワードへのインポート検証、会計・税務の確認は未完了です。取引明細には個人情報が含まれるため、公開前にプライバシー・利用規約も整備してください。

## 起動とテスト

Node.js >= 20（テスト）とPython3（簡易サーバー）を使います。`npm test` は単体テストに加えて **Chrome/Chromiumによる実ブラウザE2Eテスト** も実行するため、ブラウザをインストールしてください（GitHub Actionsでは自動セットアップ）。npmパッケージの追加インストールは不要です。必要なら `CHROME_PATH=/path/to/chrome npm test` でブラウザ実行ファイルを指定できます。

```bash
npm test
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000` を開き、「サンプルで試す」を選択してください。実データはサーバーへ送信しません（ブラウザ側のJavaScriptで処理します）。外部CDNやAI APIは利用していません。

## 使い方

1. CSVを読み込み、取引ID・日付・金額・**支払ステータス**の4列を対応付ける。予約ステータス列があれば、支払ステータスとは別に必ず指定する。
2. 検査を実行し、重複・日付異常・未決済・キャンセル等をレポートする。
3. 必要に応じて過去に出力した**元CSV**を比較用に選ぶ（会計に既に取り込んだかどうかは分からない）。
4. 勘定科目を**利用者が**指定し、画面の**出力前チェック**で税区分・取引Noの未設定と未検証の会計判断を確認する。確認チェックを入れ、仕訳候補CSVをダウンロードする。
5. 会計ソフトの公式サンプルフォーマットとCSVを照合し、税区分などの必要事項を修正したうえで利用者が取り込む。

## 実装済み

- UTF-8 / Shift_JIS CSV、引用符・埋め込み改行を処理
- 検査レポートの「元CSV行」は空行や引用符内改行を含む実際の物理行番号を表示し、元ファイルとの照合を容易にする
- 日付・正の整数金額検証（カンマ位置の不正、任意の文字列が付いた日付、不正な時刻は要確認へ）
- **候補行の金額合計／要確認行の金額合計／金額不明行数**を分けて画面表示。合計はBigIntで正確に計算し、重複・未決済・取消を含む要確認額を売上額に混ぜない。どちらの合計も会計上の売上・入金確定額ではない（合成CSVの単体・ブラウザテストで検証）。
- 申込・予約・来客・購入日時を取引日として手動指定しても、会計取引日としての根拠が未確認なため要確認へ分類する（正しい決済日／計上日を別途確認する必要あり）。「購入日時」は自動マッピングもしない
- 予約/取引IDのファイル内重複検出（重複している**両方**を要確認）
- 取引ID・取引日・金額・支払ステータスの4項目を同じCSV列へ重複割当てした場合は検査を拒否（ブラウザ画面だけでなく解析ロジックでも検証）
- 別CSVのIDとの照合（任意）。過去CSVの取引IDに前後の空白・改行・タブ等がある場合は照合キーを勝手に変更せず、元CSV行番号を示して検査を停止（元データの確認が必要）。**過去の検査レポートを比較する場合は「取引ID」列を指定し、判定が「候補」の行だけを照合**します。「要確認」（未決済等）だった行が後日決済済みになっても、過去レポートの存在だけで重複扱いしません。通常の元CSVを比較する場合は従来どおり全IDを照合します。 検査レポートの列追加・列順変更・判定列名変更を検出した場合は、要確認行を既出力と誤認しないよう照合を停止します。**「候補」は実際に会計へ取り込んだ証明ではありません**
- `=`, `+`, `-`, `@` で始まる取引IDは、検査レポートで数式対策のため先頭にアポストロフィが付くと元IDと一致しなくなるため、仕訳候補にせず要確認に分類。数式対策で変換された可能性がある過去の検査レポートは照合を停止し、元CSVの正確なIDで再確認する（通常のIDは従来どおり照合可能）
- **「ステータス」「予約ステータス」「予約状況」など予約状態を示す列を、支払ステータスとして手動指定した場合は解析を拒否**（STORES予約の公式項目では予約状態と支払状態は別）。支払状態の列が不明な場合は仕訳候補を生成しない。支払済みと明示された支払ステータスのみ候補。予約ステータス列を指定した場合は、**確定と判定できる値（現時点では「確定」「予約確定」「confirmed」）以外を要確認**に分類。「承認待ち」や未知の状態は支払済みでも出力しない。実CSVの全ステータス値は未検証
- **複数の支払状況列／予約状況列がある場合、値が矛盾する行（片方が空欄の場合を含む）は要確認**に分類し、仕訳候補から除外します。列名が似ていても同じ意味・同じ決済単位とは限らないため、元CSVの仕様を確認してください。
- マネーフォワード会計「仕訳帳」の27列（A〜AA）ヘッダー出力
- 摘要が200文字を超える候補は黙って切り詰めず、元CSV行を示して出力を停止（取引ID欠落・絵文字破損を防止）。元CSVを修正して再検査する
- 仕訳候補CSVの出力前監査（27列・取引日・勘定科目・貸借金額に加え、同一ファイル内の完全一致する仕訳行、および数式として解釈されうるセルを検出して出力停止。**借方税額・貸方税額は公式仕様どおり空欄または0のみ許可**。税区分と取引Noの未設定を件数付きで警告し、**取引Noを指定しても再インポートは新規仕訳になる**と常時注意喚起）。未確認の会計判断は自動確定しない。引用符付きセル内に改行がある場合も、監査エラーには実ファイルの物理行番号を表示
- ブラウザ内処理、検査レポート・候補CSVダウンロード、Node組み込みテストとChromiumの画面操作E2Eテスト
- CSVの読み込み失敗時は前回の検査結果を破棄し、非同期で古い読み込みが後から完了しても最新CSVを上書きしない（単体テストあり）
- 過去CSVの読み込み中に予約CSV・列マッピング・比較CSVを変更しても、古い分析結果やエラーを再表示しない（非同期競合の回帰テストあり）

## 重要な注意

- STORES予約の予約一覧CSVには**「ステータス」と「支払ステータス」が別項目**として含まれます。支払済みでも予約がキャンセル済みの場合があるため、両者を混同しないでください。予約ステータスを未指定の場合はキャンセルを検出できません。公式の主な項目一覧では**決済日や決済単位の一意IDは確認できません**。予約日時を仕訳日に自動採用しません。取引日とIDの根拠を必ず確認してください。
- 決済日を取引日に使用するかどうかは事業者の会計方針によります。決済済みでも売上仕訳を確定してはいけません。
- 現状、借方／貸方は利用者が一律指定します。前受金や回収・手数料等を処理する場合には不十分です。
- マネーフォワード側は**毎回のインポートで新規仕訳が追加**されます。**同じ取引Noを指定しても重複防止にはなりません**（既存Noと衝突した場合は別Noで取り込まれます）。二重取り込みに注意してください。
- 取引No・税区分等を空欄にしています。**出力前チェックはCSVの構造検査であり、実際の税区分、勘定科目の存在、売上計上時点、再インポート防止を保証しません。**
- 読み込むCSVは **12 MiB以下・50,000データ行以下・200列以下** に制限します。ファイルサイズはメモリへ読み込む前に確認し、行数・列数はパース中に制限します。過去照合CSVにも同じ上限を適用します。これらは試作版の資源保護上限であり、STORES予約の公式制限ではありません。レポートの画面表示は先頭200行です（ダウンロードは全件）。

## 事業仮説と検証基準

対象候補：STORES予約を利用し、マネーフォワード会計への手入力・CSV加工をしている小規模事業者。商品仮説：初期版は買い切り、実務の継続照合が成立すればサブスクリプション版を検討。

**次の重要タスク**：サンプルCSV提供者の同意を得て匿名化された予約と決済CSVを入手 → 正式な仕様と照合 → 正確な勘定科目・税区分を専門家確認 → 5人の見込み客で課題検証。販売は有料需要の確認後。
